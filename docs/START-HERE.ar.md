# ابدأ هنا: أول مشروع لعبة لك

## معك موبايل فقط؟ افتح المعاينة المباشرة

يوجد الآن نموذج ويب قابل للعب مباشرة في المعاينة داخل المحادثة، دون تنزيل ZIP أو تثبيت محرك. اضغط «ادخل واحتي»، ثم استخدم العصا وزر التفاعل. «اصنع» لتحويل الخشب إلى ألواح، و«ابنِ» لوضع قطع أمامك. البوصلة الصغيرة بجوار اسم الوادي تبدّل النظرة العامة.

في نسخة الوادي الجديدة: الكاميرا خلف الشخصية. لبناء بيت صغير: أرضية ← حوائط على الحواف ← مدخل وشباك ← سقف. زر «تغيير» يبدل بين ٦ قطع؛ «تدوير» يختار الحافة. يمكن تركيب القطع على نفس الأرضية؛ السقف يحتاج حائطين. اقرأ سبب المعاينة الحمراء في بطاقة التفاعل. الكوخ الموجود سلفًا للزينة؛ ابنِ بيتك من زر البناء. البوصلة تبدل النظرة العامة.

هذا نموذج Three.js مستقل عن محرك Godot، وليس APK. يحتاج اتصالًا لفتحه؛ بعد التحميل لا توجد خدمة شبكة للعب. الحفظ خاص بنفس المتصفح ورابط المعاينة، وليس نسخة سحابية أو حفظًا مشتركًا مع أندرويد. الشرح التالي يخص **مشروع Godot والتصدير الأصلي فقط**، ولا تحتاج تنفيذه لرؤية نموذج المتصفح.


## ماذا لديك الآن؟

مشروع **Godot 3D** باسم مؤقت «واحة صغيرة». كل شيء محلي ودون نت، بهدف التعلم وتجربة الجمع والبناء والزراعة. ليس نسخة من شخصيات أو رسومات Bloxfun، وليس لعبة كاملة أو APK جاهزًا.

**مهم:** لم نستطع تنزيل وتشغيل المحرك هنا. الملفات اجتازت فحوص المصدر، لكن يلزم فتحها داخل Godot وتشغيل اختبارات المحرك قبل اعتبارها قابلة للعب على جهازك. أي خطأ يظهر أرسل نصه أو صورته دون بيانات حساسة.

## أسهل طريق: كمبيوتر متاح

1. نزّل Godot **4.4.1 Standard** من الموقع الرسمي أو مستودع `godotengine/godot-builds`؛ لا تحتاج شراء محرك أو تثبيت نسخة .NET.
2. فك ضغط المشروع في مجلد مستقل.
3. من مدير مشاريع Godot اختر **Import** وحدد `project.godot`.
4. انتظر استيراد الخط وظهور المشروع ثم اضغط **F5**.
5. إذا ظهر خطأ، افتح تبويب **Debugger** وانقل أول رسالة خطأ كما هي؛ لا تعِد تثبيت كل شيء عشوائيًا.

يمكن استخدام محرر Godot لأندرويد للعمل على الهاتف إذا كان الإصدار والجهاز يدعمانه، لكن لا نفترض أن تصدير APK يعمل عليه بنفس خطوات الكمبيوتر. لو معك هاتف فقط، أخبرني بذلك قبل تجهيز سلسلة تصدير، ولا تدفع مقابل أي أداة.

## أول خمس دقائق داخل النموذج

- تحرك بالعصا أو WASD، واقترب من شجرة أو صخرة.
- زر **جمع** يضيف وحدة؛ كل مورد يعطي 3 وحدات قبل أن يختفي.
- افتح **صنع**: كل خشبتين تصنعان لوحًا واحدًا. اصنع لوحين.
- اجمع حجرًا ثم افتح **بناء** واختر الأرضية. تحرك لتغيير المعاينة أمامك؛ اللون الأخضر يعني مكانًا وموارد صالحين، والأحمر يعني تعذر الوضع.
- لا يمكن البناء فوق الأحواض أو الموارد أو نقطة البداية؛ ولا وضع قطعتين في خلية واحدة.
- اذهب للأحواض الأربعة: **ازرع ← اسقِ ← انتظر 30 ثانية لعب ← احصد**. الحصاد يعطي محصولين وبذرتين.
- اضغط **حفظ**، ثم أغلق وأعد الفتح واختبر رجوع التقدم.

القائمة توقف الحركة والنمو. لا ينمو الزرع أثناء إغلاق اللعبة، ولا توجد دورة ليل ونهار أو عطش يتجدد بعد الري في هذا النموذج.

## تصدير أندرويد لاحقًا دون شراء خدمات

هذه خطوات إعداد، وليست إثباتًا بأن APK صدر أو اشتغل:

1. افتح اللعبة على الكمبيوتر وحل أخطاء المحرك أولًا، ثم نفذ اختبارات `README.md`.
2. من Godot ثبّت **Export Templates** المطابقة تمامًا لإصدار المحرك.
3. جهّز **OpenJDK 17** وAndroid SDK وفق توثيق تصدير أندرويد لنفس إصدار Godot. تفاصيل SDK/build-tools تتغير؛ اتبع متطلبات الإصدار بدل نسخ أرقام قديمة.
4. في **Editor Settings → Export → Android** حدد Java SDK Path وAndroid SDK Path.
5. في **Project → Export** ستجد `Android (debug prototype)`. الإعداد يستهدف arm64 فقط ودون إنترنت. لو جهازك لا يدعم arm64 نحتاج تعديلًا بعد معرفة موديله.
6. أنشئ مجلد `build`، واختر **Export Project** مع **Export With Debug** للتجربة. يلزم مفتاح debug حسب إعداد Godot؛ لا تضع مفاتيح أو كلمات مرور داخل المستودع.
7. انسخ APK إلى هاتفك وثبّته بإذن التثبيت من المصدر الذي اخترته. أو استخدم USB debugging و`adb install -r build/pocket-oasis-debug.apk` بعد إعداد ADB.
8. اختبر دون شبكة، ثم اختبر الخلفية والاستئناف وإعادة الفتح. لا تستنتج الأداء من RAM أو المساحة فقط.

معرّف `org.pocketoasis.prototype` واسم اللعبة مؤقتان. نسخة debug ليست إصدار متجر: تحتاج قبل النشر هوية نهائية، معرفًا تملكه، توقيع release سريًا، مراجعة API target والسياسات الحالية، وترخيص المحرك والخط وسياسة خصوصية تعكس البيانات الفعلية. لا ترفع مفتاح التوقيع أو كلمات مروره إلى الشات أو Git.

## الحفظ والتلف

الحفظ داخل `user://` الخاص بالتطبيق، وليس بجوار كود المشروع. ملفات `island-save.json` و`.bak` تحفظ الحالة الحالية والسابقة. عند تلف الأساسي نجرب النسخة السابقة، وقد تفقد آخر تقدم بين الحفظين. إذا فشل الاثنان يتوقف اللعب والحفظ حتى تختار **القائمة → عالم جديد → تأكيد**؛ لا نكتب فوق ملف تالف تلقائيًا عند الفشل.

التطبيق يحاول الحفظ كل 20 ثانية لعب وعند الخلفية، لكن إيقاف النظام المفاجئ قد يسبق إشعار الحفظ؛ احفظ يدويًا قبل الإغلاق المهم. حذف بيانات التطبيق أو إلغاء تثبيته قد يحذف التقدم. لا يوجد حفظ سحابي أو نقل أجهزة.

## المرحلة التالية بعد أول تشغيل

نصلح أخطاء التشغيل أولًا، ثم نحسّن اللمس والكاميرا على هاتفك ونقيس جلسة 20 دقيقة. بعدها فقط نضيف محتوى وأصواتًا أو خصائص أخرى. لا دفع أو خدمات أو نشر دون موافقتك. يرجى تزويدي بموديل الهاتف عند الاختبار؛ 12GB RAM و256GB تخزين وحدهما لا يحددان GPU أو المعمارية.
