# سجل التنفيذ: النموذج الفردي المجاني

## قرار النطاق الجديد — 2026-11-27

المستخدم أكد أنه يعمل منفردًا بخبرة بسيطة، لا يريد الإنفاق حاليًا، ثم وافق على اقتراح نموذج Godot صغير ثلاثي الأبعاد دون إنترنت. RAM الهاتف 12GB ومساحته 256GB؛ الموديل والمعالج غير معروفين. لا نستنتج الأداء منهما.

**هذا يلغي اعتماد خطة Unity والفريق التجاري الكبيرة للمرحلة الحالية.** الملفات الأقدم `architecture.md` و`roadmap.md` أبحاث تاريخية لتوسع محتمل فقط. لا MMO أو خادم أو مشتريات أو تكاليف خدمات الآن.

## التحقق

- نجح parser/lint/format للسكربتات باستخدام gdtoolkit 4.3.4.
- نجحت 6 اختبارات Python لهيكل المشروع والمراجع والموارد وإعدادات Offline والتغليف والتوكنات.
- فحص التباين: 7 أزواج، صفر إخفاق AA.
- اختبارات GDScript للحقيبة والتصنيع والبناء والزراعة والتحقق والحفظ مكتوبة، وكذلك smoke test للمشهد؛ **لم تنفذ** لغياب المحرك.
- محاولة تنزيل Godot 4.4.1 من GitHub فشلت عند مضيف ملفات الإصدار المحجوب في البيئة. لا JDK/Android SDK أو ADB مثبتة؛ لا تصدير Android أو اختبار جهاز أو قياسات أداء.
- أضيف workflow لتشغيل فحوص المصدر والمحرك على GitHub عند push؛ لم ندفع تغييرات أو نشغل workflow.

## القادم

فتح المشروع في Godot وتشغيل اختبارات المحرك أولًا، إصلاح أي أخطاء فعلية، ثم تجربة اللمس والأداء على هاتف المستخدم قبل توسعة المحتوى. إن كان الهاتف هو الجهاز الوحيد المتاح نحدد مسار التحرير والتصدير المناسب قبل أي إنفاق. لا commit أو push أو خدمة مدفوعة أو نشر دون موافقة صريحة.


## تحديث: المستخدم لديه هاتف فقط ويريد اللعب الآن

أضيفت نسخة معاينة ويب بـThree.js في `web/` مع Vite، مع الإبقاء على مشروع Godot. استخراج ثوابت العالم من مصدر Godot قابل للتحقق باستخدام `npm run check:world`، لكن المحركين ومنطقي اللعب وملفات الحفظ منفصلان بوضوح.

تم تشغيل نسخة الويب واختبار WebGL ولمس موبايل آلي فعليًا: نجح 15 اختبار منطق و24 تحقق متصفح و6 اختبارات هيكل Python وbuild إنتاج. النموذج يحتوي الجمع والتصنيع والبناء والزراعة والحفظ وإعادة التحميل، مع واجهة عربية مناسبة للوضعين الطولي والعرضي. لا APK ولا نشر متجر ولا اختبار جهاز حقيقي. الخادم الذي يظهر داخل Arena معاينة مؤقتة، وليس نشر إنتاج مدفوعًا أو دائمًا.


## تحديث الوادي بعد موافقة المستخدم على التصور الثاني

استبدلت معاينة الويب ذات الكاميرا العمودية بكاميرا منظور خلف الشخصية، تضاريس مشتركة بين الأقدام والرسم، نهر وجسرين وخوض أبطأ للماء، أشجار وتلال وزهور ومنضدة وكوخ زينة. شخصية أصلية أكبر بحقيبة ومجرفة وحركة أطراف. خامتا مرج وخشب مولدتان خصيصًا وليستا من الألعاب المرجعية. أجزاء البيت: أرضية وأربع حواف مستقلة (حائط/شباك/مدخل) وسقف، مع بقاء السياج. الوصفات الجديدة تخص الويب ولا تعدّل البيانات المستخرجة من Godot. الحفظ v2 يقرأ ويرحّل v1 ويحافظ على مراكز الجدران القديمة. لا هدم أو استرداد موارد أو بناء متعدد الطوابق.

22 اختبار منطق و29 تحقق متصفح نجحت، بما فيها بيت مبني باللمس ثم محفوظ ومعاد تحميله. مراجعة صور فعلية طولي وعرضي وسطح مكتب كشفت انسداد الكاميرا بالأشجار؛ عولج باختفاء العوائق بين العدسة واللاعب، مع batching للزينة الثابتة. الاختبار عبر Chromium/SwiftShader، وليس قياسًا لجهاز حقيقي. الصورة الفنية المرجعية ليست لقطة للعبة ولا تطابقًا مضمونًا. لم تُنشأ commits أو PRs أو خدمات مدفوعة.

نجح فحص إنتاج الوادي أيضًا، بما فيه ترحيل حفظ v1 عبر متصفح الإنتاج دون hook تطوير. نجح تحقق ثوابت Godot و6 اختبارات هيكل Python مجددًا. بقي تحذير حجم chunk من Vite (~534kB قبل gzip)، لا أخطاء build. الخادم النهائي على منفذ 5173؛ أوقف خادم التطوير الاختباري حتى لا تظهر معاينتان مختلفتان للمستخدم.
